# RFC-2026-003 — Yape y Plin

## Alcance

Dos métodos nuevos detrás de `IMetodoPago`: `PagoYapeSimulado` y `PagoPlinSimulado`.
El checkout presenta las opciones registradas y muestra el QR del método elegido.
Los QR son imágenes de referencia: no validan pagos ni generan cobros automáticos.

## Persistencia y compatibilidad

- `pagos.metodo` ya es una columna `int`, sin conversión a texto.
- `Simulado = 1` conserva los pedidos anteriores.
- `Tarjeta = 2`, `Transferencia = 3`, `Yape = 4`, `Plin = 5` identifican pagos nuevos.
- Cambio común: `IMetodoPago` expone `Metodo`; `PagoService` lo añade al resultado
  de la estrategia y `PedidoService` lo persiste. La selección continúa usando
  `SingleOrDefault` sobre los métodos registrados.
- No hay cambios de tablas, columnas, configuraciones ni migraciones.

## Archivos de los QR

Colocar las imágenes originales en:

```text
BlackCode.Web/wwwroot/img/pagos/yape-qr.png
BlackCode.Web/wwwroot/img/pagos/plin-qr.png
```

Se sirven mediante `/img/pagos/yape-qr.png` y `/img/pagos/plin-qr.png`.
Estos archivos se incluyen en la publicación Web y deben acompañar el futuro PR.
La ausencia de un archivo muestra un aviso, sin inventar códigos QR.
Después de copiar las imágenes, recargar el checkout para que el servidor las detecte.

## Comprobación funcional

1. Entrar como cliente, agregar un producto y abrir el checkout.
2. Verificar las opciones Tarjeta, Transferencia, Yape y Plin.
3. Elegir Yape y Plin: mostrar solo la imagen correspondiente y el total del pedido.
4. Elegir Tarjeta o Transferencia: ocultar los QR.
5. Corregir un teléfono inválido y comprobar que se mantiene el método elegido.
6. En Development, marcar «Forzar rechazo»: conservar carrito y stock, sin crear pedido.
7. Completar una compra de prueba con cada método y abrir su detalle.
8. Comprobar en `pagos.metodo` los valores 2, 3, 4 y 5 respectivamente.
9. Abrir un pedido anterior con método 1 y verificar que se conserva.
10. Comprobar el checkout en una pantalla móvil.

## Pruebas automáticas

```text
dotnet build BlackCode.slnx
dotnet test BlackCode.slnx
```

`PagoServiceTests` comprueba el registro DI, resultados, montos inválidos y rechazo.
`CheckoutPagoTests` usa una base SQLite temporal para comprobar el método guardado,
el stock, la reversión ante rechazo y los pedidos históricos. El modelo MySQL se
compara con el snapshot sin ejecutar migraciones ni abrir conexiones.
SQLite es una dependencia exclusiva del proyecto de pruebas.
